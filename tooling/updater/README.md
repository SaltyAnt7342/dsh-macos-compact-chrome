# DSH 紧凑版 · 自动更新工具

这个文件夹负责在官方 DSH 发版后，自动检查、重建并**直接替换安装、重启**紧凑版，不再需要手动下载 DMG 或拖拽安装。

## 文件

- `检查更新.command` —— 双击手动检查一次。
- `重建紧凑版.command` —— 双击按最新官方源码重建，完成后自动关闭、替换并重启紧凑版（约 5–10 分钟）。
- `安装并重启.command` —— 已有新 DMG 时，直接安装并重启（会先确认）。
- `安装每日检查.command` / `卸载每日检查.command` —— 开启/关闭每日后台检查。
- `check-update.sh` / `rebuild.sh` / `install-update.sh` —— 实际脚本。
- `version.json` —— 当前紧凑版基于的官方版本。
- `update.log` —— 检查/重建/安装日志。

## 日常怎么用

1. 双击 `安装每日检查.command`。之后登录时和每 24 小时会自动检查一次。
2. 有新版时会弹窗：「稍后 / 现在重建并重启安装」。
3. 点「现在重建并重启安装」后，Terminal 会开始构建；完成后会**自动关闭紧凑版、替换 App、重新打开**。
4. 不需要再下载 DMG，也不需要拖拽安装。DMG 仍会保留一份，作为备份/手动安装用。

也可以随时双击 `检查更新.command` 手动检查。

## 它怎么工作

- 检查：通过 `git ls-remote` 读取官方仓库最新的 `dsh-v*` tag，与 `version.json` 里的 `baseVersion` 比较；同时读取 `/Applications/DeepSeek Harness.app` 的版本作为参考。
- 重建：切到新 tag → 套用 `dsh-sidebar-compact.patch` → 临时把未签名打包切到 official 品牌配置 → `pnpm install` + 打包 → 生成新 DMG → 还原构建脚本 → 在源码仓库里 `commit` 并打 tag `compact-<版本>` → 重新生成补丁。
- 安装：挂载新 DMG → 先把新 App 复制到临时目录 → 关闭紧凑版 → 备份旧 App → 替换 → 删除备份并重新打开。任何一步失败都会保留旧版或旧版备份。

## Git 版本记录

每次重建会同时更新两处 Git，并在 Terminal 打印、在 `updater/git-report.txt` 留一份：

- 源码仓库 `dsh-src`：`commit` + 标签 `compact-<版本>`。
- 工具目录 `dsh-sidebar-preview`：`commit` + 标签 `tooling-<版本>`。

以后每次项目更新后的回复里也会附上「Git 更新结果」。

## 注意

- **仍然会在本机自动重建一次**：紧凑侧栏是源码级改动，不能直接拿官方 App 覆盖。你不需要手动打包/下载，但构建那 5–10 分钟还在。如果官方仓库合并了紧凑侧栏 PR，以后就完全不需要重建。
- 更新时紧凑版会关闭再打开；当前对话会保存，重新打开后可以继续。
- 补丁和新版源码冲突时，脚本会停下来并提示；这时需要人工处理（可以找我）。
- 只检查官方源码 tag；如果官方 App 已更新但 tag 还没发布，会提示“等 tag 发布后再重建”。
- 构建出的 App 是**未签名/未公证**版本；本地同名更新不需要右键打开。
- 紧凑版和正式版共用 `~/.dsh` 数据，不要同时运行；也不要让紧凑版自动更新，否则会覆盖改动。
- 安装每日检查会写入 `~/Library/LaunchAgents/com.saltyant73.dsh-compact-update.plist`；用卸载脚本可移除。
